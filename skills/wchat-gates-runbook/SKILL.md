# 闸门跑批手册(改完代码怎么证明它没坏)

**触发条件**:你刚改了 `wchat.sh`、`test_hardwall.sh` 或 `tests/` 下任何东西,准备说"改完了"或提交。

本项目的规矩:**看不见的绿灯不算绿**。一道闸门只有同时满足"跑到底、产出机器可读结论行、结论是被固定字段守住的",它才算跑过。

## 顺序与命令(工作目录 = 仓库根)

```bash
bash tests/run_gates.sh              # 一条命令跑完全部闸门(推荐)
bash tests/run_gates.sh --list        # 只看会跑哪些、哪道被跳过
bash tests/run_gates.sh rulefail 压缩  # 只跑名字含这些子串的道
bash tests/run_gates.sh --main          # 额外加主套件 auto_test.sh unit(慢)
```

单独调试某道的原始输出时,直接跑它自己(`test_hardwall.sh`、`tests/rulefail_check.sh`、
`tests/compaction_pin_probe.sh`、`tests/audit_field_probe.sh`、`tests/probe_shapes.sh`、
`tests/skills_dir_test.sh`、`tests/traffic_replay.sh`)。

`run_gates` 判"通过"的条件是 **rc=0 且匹配到该道自己的结论行**,只满足一半都不算:
- rc=0 但没有结论行 ⇒ 中途静默退出(本项目真出过两次,一次是 `$(` 抽取过滤器把算术派生扔了);
- 有结论行但 rc≠0 ⇒ 通常它在说"该重固化基线"(回放遇到语料增长就是这个形状),别当跑过。

它刻意**不重复各道的期望数字**:总数由 `EXPECT_TOTAL` 守、规则出口数由 rulefail 的
`_seen_rules` 守 —— 抄第二份必然漂移。两个实现坑也记在这:跑子闸门不要套 `bash -c`
(实测回放被包装后 rc=1 且一行输出都没有,机制未定位,SHELLOPTS 继承与嵌套层数两个假设
已排除);`bash -n a b c` 只检查第一个文件,其余被当位置参数 —— 想查三个文件必须写三条 `&&`。

## 各道闸门在守什么 + 红了先怀疑什么

| 闸门 | 看它的哪一行 | 红了的第一个假设 |
|---|---|---|
| 全表 | `RESULT total=… pass=… fail=0 expect=517… src=<12hex>` | `expect` 与 `total` 不等 ⇒ **有断言没产生判定**(被测版本缺函数/装载缺口),不是判据错 |
| 全表 | 红条写"命令不存在:[X]" | 夹具按名字抽函数,X 没登记 —— 去 `test_hardwall.sh` 的显式名单加它 |
| rulefail | `PASS/FAIL` | 出口话术不含关键词 ⇒ 你改了 msg 没改校验;或"判据出口行数"变红 ⇒ 你加了规则没同步期望数与覆盖清单 |
| 压缩探针 | `RESULT total=29 pass=29 fail=0` | 接线锁红 ⇒ 有人删了调用点/把判据抄回调用点 |
| 审计探针 | `结论: 通过` | 缺 `root`/`pol` ⇒ 审计 JSON 字段被动过 |
| 回放 | `无新增漂移` | 审计语料增长后要先复跑再 `GEN=1` 固化,**别直接固化** |

## 当前基线(2026-09-24 实跑值,会变;以命令输出为准)
全表 **560/560 fail=0**、rulefail **123/0**、压缩探针 **29/29**、形状探针 **20/0**、技能目录 **全部通过**、
回放 **52 条一致**、主套件(unit+e2e)**全部通过** —— `bash tests/run_gates.sh --main` 的 `pass=9 fail=0`。
这是这张表**第一次**全绿:此前长期挂着两条 T23"装载口"红,真因不是装载口没实现,而是主脚本
第 44 行用了尚未定义的 `$API_KEY`(`set -u` 的夹具死在口之前)。别把这类红当环境噪音绕过去,
它同时吃掉了形状探针那道。
`src=` 是 `wchat.sh` 的 sha256 前 12 位:**两次运行结论不同,先看这个数**——它变小说明源码变了,与判据无关。

## 加断言后必须做的三件事(少一件就会"全绿但没测到")
1. 数你新加的 `expect` 行数,**加进 `EXPECT_TOTAL`**(用 `grep -c` 数,不许心算——历史上心算少 2 被总数守卫逮到)。
2. 若是新规则号:同步 `tests/rulefail_check.sh` 三处 —— 样例数组、关键词数组(两者**按位置一一对应**,插错位置会得到一条假绿)、`for id in …` 覆盖清单、`_seen_rules ==` 那个行数期望。
3. 更新 `tests/README.md` 的基线说明。

## 变异:证明你的断言是承重的
新写一条断言后,把被测那行故意改坏,断言必须变红:

```bash
MUT_SUITE=tests/compaction_pin_probe.sh /opt/homebrew/bin/bash tests/mutate_call_site.sh '<定位字面串>' '<替换文本>'
# 去掉 MUT_SUITE 就跑全表;装置会打印"定位 N 处"和"✅ 此变异可杀 / ⚠️ 未被杀"
```
装置的三条红线(它自己的注释里写着,踩过的坑):
1. **算子按语义选**,不按字面取反:`helper "$x" || return 0` 换成 `false` 和换成 `true` 是同一个变异(都会继续往下走)。
2. **必须与同路径基线比**,装置已经做了(`基线` / `变异` 两行 RESULT + comm 出的新增/消失红条数)。
3. 命中数为 0 ⇒ 它报 `⛔ 这次变异是空操作`,**别把"0 处替换"当成"变异未被杀"**。
一个已知边界:装置按字面串整行替换,**两处文本完全相同的调用点它做不到只变异其一**(需要手工按行号补一刀)。所以给同类判据留可区分上下文是有益的。

## 提交前的自我检查
提交信息里写的每个数字,必须是**这一轮实跑**的;没跑的写"未验";改了注释导致 sha 变了要重跑一次再取 sha。这条不是格式洁癖——本项目出过一次"把没跑的闸门写成跑过"的现场。
