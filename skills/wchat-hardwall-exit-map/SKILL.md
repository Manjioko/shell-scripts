# 硬墙规则 → 合法出口(撞墙时读这一份)

**触发条件**:输出里出现 `⛔`、`被硬墙拒绝[规则 …]`、`错误:…被拒绝[硬墙 H…]`,或 auto 把命令判成拒。

## 第一原则:照红条里的"替代:"做,不要换写法绕
每条规则的 `hd_msg` 都以 `替代:` 结尾,**那是判据作者写死的合法出口**。撞墙后的三种反应里:
- ✅ 照替代方案做,或直接问人 —— 这两种是被设计期望的行为;
- ❌ **改写路径重试同一目标**、❌ 拆成两条命令躲开分段判据、❌ 换个等价工具名 —— 这三种是绕路,而绕路成功的下一次,就没有任何判据在看这件事了。
红条里明确写着"这不是用户拒绝,是代码级红线",意思就是:重面试、换写法都不会通过,只会白烧轮次。

## 速查表(规则号取自主脚本原文)

| 号 | 守什么 | 合法出口 |
|---|---|---|
| H1 | 提权 `sudo/doas/su/pkexec` | 把命令原样交给人,由人执行 |
| H2 | 下载即执行 `curl…\|sh` | 先只下载到 /tmp,**读内容**,再决定装不装 |
| H3 | 指向根/家/系统目录的删除 | 删工作目录内具体路径;要清 home 交人工 |
| H4 | 磁盘级(dd/mkfs/分区) | 一律人工,无替代 |
| H5 | 写/删 `~/.xxx` 配置与凭据目录 | 写到工作目录内或 /tmp;确实要改 dotfile → 交人工 |
| H6 | 读凭据(.npmrc/.netrc/.pypirc/私钥/凭据目录) | 不要读,也不要"顺手检查";需要结论就说缺什么 |
| H7 | 强推/删远端分支/改写已发布历史 | 交人工;或改用新提交而非 amend/rebase |
| H8 | 电源与系统服务(`shutdown/reboot/pmset/launchctl bootout·unload·kill`) | 需要"让配置生效"→ 交人工(见下"生效链") |
| H9 | 批量杀进程/杀宿主(`pkill`、`killall` 命中 wchat/bash/node/python/Terminal/Finder/Dock)、`kill -9` 形态 | **精确 `kill <PID>` 是通的**,`run_in_background` 会回吐 PID —— 用 PID,不要用 pkill |
| H10 | 外发密钥/凭据/.env(上传动作 + 敏感内容同时出现) | 只提交用户明确要求的非敏感数据 |
| H11 | 重定向写系统路径 | 写到工作目录内或 /tmp |
| H12/P3 | 越界写目标(工作根之外) | 写工作根内;确需越界 → 人启动时 `--allow-write <路径>`(仅 `-auto=full`) |
| H13 | 写目标在审批层**不可解析**:`defaults write/delete`、`plutil -replace/-insert/-convert`、`osascript`、`launchctl load/unload`、`sqlite3` 带 DML、`git config --global/--system`、`security add-*/delete-*`、`networksetup`、`tccutil reset`、`xattr -w`、`htpasswd` | 用文件工具改工作目录内的配置;或把"要改哪个键、改成什么"写清楚交人工执行 |
| H14 | **安装**(brew/pip/npm/pnpm/yarn/gem/cargo/go/uv/apt/dnf/yum/apk/composer 的 install/add/i/tap) | 退出重启加 `--allow-install 包名1,包名2`(只点你认识的名字);或把安装交人工。**换源形状(`--registry`、`--index-url`、`-i http…`、`PIP_INDEX_URL=`、`brew tap <URL>`)有授权也拒** |

路径判据:`P1` 凭据/会话数据(`~/.ct/history`、`~/.ct/config`、私钥),`P2` 系统路径与主目录顶层/隐藏目录,`P3` 一般越界目标。

## 三条"看起来是 bug,其实是设计"
1. **只读命令也可能被拦**:`ls -la ~/.ct 2>&1` 命中 H5/H6 的形状是"路径出现在参数位 + 掩码只保护紧跟的一个操作数"。别去修判据,换写法(不引用凭据路径)。
2. **引号里的散文参与判定**是这个族的已知历史问题(T28 字面量掩码、H14 的"必须段首")。新写判据时:**全文匹配 = 必误伤**。
3. **规则号会串味**:同一条命令换个规则号继续被拦(H5/H6 那批),不代表判据坏了 —— 只要结论是拒,先找出口,不要先找锅。

## 生效链(改完配置怎么让它生效)——目前**没有**自动出口
`defaults`/`plutil` 撞 H13、`killall cfprefsd` 撞 H9、`launchctl` 撞 H8。结论:
- 需要 app 重载配置 ⇒ **写清楚"改了哪个键、需要重启哪个 app",交给人执行**;
- 不要为了绕过这三条去改缓存文件、删 `~/Library/Caches` 内容 —— 那是 H5 的家门,而且比"重启 app"难回滚得多。

## 想知道某条命令会被判什么
最可信的办法是**真跑一次**看红条(红条自带规则号与替代方案)。在会话外模拟判据要靠抽函数跑,夹具和真链路本来就不同口径(本项目为此专门在 rulefail 里加了"调用点接线"断言)——模拟结论只当参考,别当证据写进提交信息。
