# 复现之前不许有理论(根因协议)

**触发条件**:出现"为什么"、"是不是因为"、"我怀疑是 X"、"代码看着没问题但行为不对"。

## 铁律
1. **没有可重复失败的最小命令,就不许提根因。** 先造出那条命令(一行 bash、一个断言、一个 `-st` 任务都行),它的价值是:此后每一步都能问"这解释了它吗"。
2. **每个假设必须可证伪**,写成"若 X 为真,则应当观察到 Y",然后**去看 Y**。看不了就标成猜测,别排版成结论。
3. **一次只动一个变量。** 同时改三处再跑,红了你不知道是谁。
4. **改完必须三件事**:复现命令从红变绿;原有闸门仍绿(`wchat-gates-runbook`);要么加一条防回归断言,要么明说"这条没保护"。
5. 证据不足时,**说"我现在不知道"比给一个像样的理论便宜得多**。

## 结论必须带等级
写任何判断时标一类,并给出**支撑它的那一条命令输出**:
- **实测**:贴命令与输出。
- **推断**:从代码形状/机制推出来的,写清"没跑过"。
- **猜测**:没有依据的,必须写成猜测,或干脆不说。

"我把整条链都推断了一遍然后提交了"是这类项目里最贵的一种错 —— 它会让下一个人把结论当前提继续往上盖。

## 反例(都是本项目真实发生过的形状,不需要指名)
| 当时的"理论" | 实际情况 | 少做了哪一步 |
|---|---|---|
| 文件消失 = 进程 cwd 解链导致路径解析错 | 写入真的成功了,只是**工作根本来就是另一个目录**;而回显只有相对路径,看起来像被删 | 没有先"把那个文件找出来"(它在),就直接给了解释 |
| 这套东西"没有回退/快照原语" | 三层都在(会话回滚点、逐文件备份、退出时打印回滚命令),只是不在我读过的那几百行里 | 只 grep 了一个区段就把"没找到"说成"不存在" |
| 照着注释去 grep 某个名字,找不到 ⇒ 判据坏了 | 注释里的行号与变量名早已过期,那个赋值行根本不存在 | 没先确认锚点还在 |
| 盘上判据实测不拦、会话里拦 ⇒ 判据写错了 | 会话进程里跑的是**旧代码**;盘上判据是对的 | 没有版本证据(现在:结论行 `src=`、审计 `pol`) |

四条的共同点:**理论都合理,而且都能自圆其说;区别只在有没有一条能重复失败的命令压着它。**

## 与"先复现"配套的两个习惯
- **把偶然变必然**:能稳定复现的 bug 才好查,也能反过来验证修复。查不出稳定复现路径时,先去找夹具/最小输入,而不是去读更多源码。
- **修完把报错变成断言**:复现命令本身就该进测试(或至少进技能/提交信息)。否则下一个同族 bug 还要再花一次同样的时间。
